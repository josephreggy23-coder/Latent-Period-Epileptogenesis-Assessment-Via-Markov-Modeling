# Reproducibility

## Deterministic default run

The committed benchmark uses:

- template seed: `42`;
- 60 fish per arm;
- 70%/30% fish-level split;
- HMM candidates: 2, 3, and 4 states;
- three train-only cross-validation folds;
- 1,000 bootstrap iterations for forecast intervals.

Run the committed placeholder demonstration with:

```bash
tbi-analyze --allow-placeholder-data --output-dir build/demo-results
```

This command leaves the committed template and results untouched. A full
deterministic reset is deliberately guarded:

```bash
python -m tbi_markov --force-reset-demo --output-dir build/reset-demo-results
```

For labeled measured-data adaptation, follow the README workflow, supply
explicit `--data-dir` and `--output-dir` paths, and run `tbi-analyze` only after
all records are marked `analysis_ready`.

## Output contract

The pipeline writes:

```text
data/template/
├── tbi_4_6dpf_lfp_timeseries.csv
├── tbi_4_6dpf_fish_outcomes.csv
├── tbi_4_6dpf_dlc_behavior.csv
└── tbi_4_6dpf_dataset_manifest.json

results/
├── figures/
├── tables/
├── TBI_MODEL_RESULTS.md
└── tbi_model_metrics.json
```

The workbook and committed manifest are reference snapshots of the initialized
seed-42 cohort. Editing the CSVs invalidates the manifest hashes, and the
workbook is not regenerated by the Python pipeline.

## Integrity controls

- The manifest records SHA-256 hashes for each normalized CSV.
- Same-seed generation is tested for byte-stable table content.
- Feature allowlisting prevents protocol, dose, behavior, or truth leakage.
- Preprocessing is fit on training fish only.
- Train/test fish IDs are disjoint.
- QC gaps terminate sequences instead of shortening time.
- Prefix invariance ensures a DPF5 forecast does not depend on DPF6 features.
- Forecast tests verify the transition-matrix propagation horizon.
- Rank-based forecast metrics use probabilities serialized at six-decimal
  precision, preventing microscopic posterior tails from creating artificial
  orderings or JSON/CSV mismatches.
- The metrics JSON records input hashes, run configuration, software versions,
  convergence history, emission means/variances, scaling, and state mappings.

## Verification

```bash
python -m pytest
python -m compileall -q src scripts
```

CI repeats these checks across supported Python versions on every push and pull
request.

## Custom runs

```bash
tbi-initialize --seed 101 --n-per-arm 80 --output-dir data/custom-template
tbi-analyze --allow-placeholder-data \
  --data-dir data/custom-template \
  --output-dir build/custom-results \
  --seed 101 --test-fraction 0.30 --states 2 3 4
```

The initializer refuses to overwrite existing normalized files unless
`--force` is supplied. Keep custom outputs outside tracked `results/` unless
you intentionally intend to refresh the committed reference benchmark.
